## 1. Gradio Chatbot  

- `gr.Blocks` 안에 컴포넌트를 배치하고, 컴포넌트의 **이벤트에 함수를 연결**해서 챗봇을 만듦  

| 컴포넌트 | 역할 | 값의 형태 |
| :--- | :--- | :--- |
| `gr.Textbox` | 사용자 입력창 | `str` |
| `gr.Chatbot` | 대화 기록을 보여 주는 채팅창 | `{"role", "content"}` dict의 리스트 |
| `gr.Button` | 클릭 이벤트를 받는 버튼 | - |

```python
def chat_respond(message, chat_history):
    response = llm.invoke([{"role": "user", "content": message}])

    chat_history.append({"role": "user", "content": message})
    chat_history.append({"role": "assistant", "content": response.content})
    return "", chat_history

with gr.Blocks() as demo:
    chatbot = gr.Chatbot(label="채팅창")
    msg = gr.Textbox(label="입력")

    msg.submit(chat_respond, inputs=[msg, chatbot], outputs=[msg, chatbot])

demo.launch()
```

- `role`은 `user`(사용자) / `assistant`(챗봇)로 구성 → 채팅창은 이 리스트를 그대로 그려 줌  

### 1-1. `msg.submit(fn, inputs, outputs)`  

- Enter를 누르면 실행할 함수를 등록하는 메서드  

| 인자 | 뜻 |
| :--- | :--- |
| `fn` | 이벤트가 발생했을 때 실행할 함수 |
| `inputs` | **현재 값을 꺼내** 함수의 인자로 넘길 컴포넌트 목록 |
| `outputs` | 함수가 돌려준 값을 **넣을** 컴포넌트 목록 |

```
inputs=[msg, chatbot]    →  chat_respond(message, chat_history)
    - msg에서 message를, chatbot에서 chat_history를 추출

return "", chat_history  →  outputs=[msg, chatbot]
    - ""를 msg에, chat_history를 chatbot에 등록  
```

- 첫 번째 반환값 `""`가 `msg`에 들어가고, 전송 후 입력창이 비워짐  

### 1-2. `return` vs `yield`  

| 구분 | `return` | `yield` |
| :--- | :--- | :--- |
| 값을 돌려주는 횟수 | 한 번 | 여러 번 |
| 돌려준 뒤 | 함수 종료 | 그 자리에서 **멈췄다가** 다음 값을 요청받으면 이어서 실행 |
| 함수를 호출하면 | 바로 실행되고 결과 반환 | 실행되지 않고 **제너레이터 객체**만 만들어짐 |

```python
def count_up(limit):
    for n in range(1, limit + 1):
        yield n               # 값을 하나 내보내고 멈춤

for value in count_up(3):     # for 문이 값을 요청할 때마다 한 단계씩 실행
    print(value)
```

- Generator(제너레이터): `yield`가 들어 있는 함수  

- 제너레이터는 사용한 이후 다시 쓰려면 함수를 다시 호출해야함  

### 1-3. 스트리밍 챗봇  

| 메서드 | 응답 방식 |
| :--- | :--- |
| `llm.invoke()` | 답변이 **완성된 뒤** `AIMessage` 하나를 반환 |
| `llm.stream()` | 답변을 **chunk** 단위로 하나씩 반환 |

```python
def chat_respond(message, chat_history):
    chat_history.append({"role": "user", "content": message})
    chat_history.append({"role": "assistant", "content": ""})

    partial = ""
    for chunk in llm.stream(build_messages(chat_history, message)):
        partial += chunk.content                # 새 조각을 이어 붙임
        chat_history[-1]["content"] = partial   # 마지막 답변을 지금까지의 전체 답변으로 교체
        yield "", chat_history                  # 화면 갱신
```

- 조각만 내보내면 화면에 마지막 조각만 보이므로 누적된 전체 답변을 매번 `yield` 해야함  

- LLM은 이전 대화를 기억하지 못하므로 `chat_history`를 매번 함께 보내야 맥락을 유지 가능(`build_messages()`가 해당 역할 수행)

## 2. LangChain Tool  

- Tool: LLM이 사용할 수 있게 만든 외부 함수

- LLM은 도구를 직접 실행하지 않고 "이 도구를 이 인자로 호출해 달라"는 요청만 전달함 

```
질문 → LLM → tool_calls(요청) → [코드가 도구 실행] → ToolMessage(결과) → LLM → 최종 답변
```

### 2-1. `@tool`  

```python
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """곱하기 숫자 a와 b를 곱합니다.""" # docstring
    return a * b

multiply.invoke({"a": 3, "b": 5})   # 인자를 dict로 전달
```

| 함수의 요소 | 도구에서의 역할 |
| :--- | :--- |
| 함수 이름 | 도구 이름 (`name`) |
| docstring | 도구 설명 (`description`) → LLM이 어떤 도구를 쓸지 판단하는 근거 |
| 타입 힌트 | 인자 스키마 (`args`) → LLM이 만들 인자의 이름과 타입 |

- `@tool`을 붙이면 일반 함수가 아니라 `StructuredTool` 객체가 됨 → `multiply(3, 5)`로 호출할 수 없고 `invoke()`로만 사용 가능  

### 2-2. `bind_tools()`  

```python
llm_with_tools = llm.bind_tools([add, multiply])
```

- `Tool`을 LLM에 연결 → 호출할 때마다 도구 정보가 함께 전달됨  

- 원본 `llm`은 그대로 두고 **도구가 연결된 새 Runnable**을 반환  

- 도구 호출(tool calling)을 지원하는 모델이어야 함  

### 2-3. `tool_calls`  

- 도구가 필요하다고 판단하면 LLM은 답변 대신 **Tool 호출 요청**을 `AIMessage`의 `tool_calls` 속성에 담아 반환  

```python
ai_message = llm_with_tools.invoke("3 곱하기 5는?")
ai_message.tool_calls
# [{'name': 'multiply', 'args': {'a': 3, 'b': 5}, 'id': 'call_abc123', 'type': 'tool_call'}]
```

| 키 | 값 |
| :--- | :--- |
| `name` | 호출할 도구 이름 |
| `args` | LLM이 질문에서 뽑아 만든 인자 |
| `id` | 이 요청의 식별자 → 실행 결과와 짝을 맞추는 데 사용 |

- 이 시점에 도구는 아직 실행되지 않음  

- 도구가 필요 없다면 `tool_calls`는 빈 리스트가 됨  

### 2-4. `ToolMessage`  

- 도구를 실행한 결과를 담아 LLM에게 돌려주는 메시지  

| 속성 | 값 |
| :--- | :--- |
| `content` | 도구의 반환값 |
| `tool_call_id` | 어떤 tool_calls에 대한 결과인지 나타내는 id |

- `tool_calls`의 항목(`name`, `args`, `id`)을 도구의 `invoke()`에 그대로 넘기면 `tool_call_id`가 채워진 `ToolMessage`가 반환됨(수동 Tool-Calling)

### 2-5. 수동 Tool-Calling  

```python
message_list = [HumanMessage("3 곱하기 5는?")]

ai_message = llm_with_tools.invoke(message_list)             # ① 호출 요청 받기
message_list.append(ai_message)

tool_message = multiply.invoke(ai_message.tool_calls[0])     # ② 도구 실행
message_list.append(tool_message)

result = llm_with_tools.invoke(message_list)                 # ③ 결과를 넘겨 최종 답변 받기
```

| 메시지 | 만드는 쪽 | 내용 |
| :--- | :--- | :--- |
| `HumanMessage` | 사용자 | 질문 |
| `AIMessage` (`tool_calls`) | LLM | Tool 호출 요청 |
| `ToolMessage` | 코드 | Tool 실행 결과 |
| `AIMessage` (`content`) | LLM | 최종 답변 |

- 대화 기록의 순서는 `HumanMessage` → `AIMessage(tool_calls)` → `ToolMessage` 

- 요청이 담긴 `AIMessage`도 기록에 넣어야 LLM이 자신이 무엇을 요청했는지 알고 결과를 해석 가능

## 3. Tavily 

- LLM 에이전트용으로 만들어진 **웹 검색 API** → 학습 시점 이후의 최신 정보를 가져오는 데 사용  

```python
from langchain_tavily import TavilySearch

web_search = TavilySearch(max_results=3, topic="general")
result = web_search.invoke({"query": "LangChain v1.0 create_agent"})

llm_with_tools = llm.bind_tools([web_search, get_schedule])
```

- `TavilySearch` 객체는 그 자체로 Tool이므로 `@tool`로 만든 도구와 같은 리스트에 넣어 연결

## 4. `create_agent()`  

- LangChain v1.0에서 에이전트를 만드는 함수 

- 모델과 도구를 넘기면 `ReAct` 루프를 자동으로 도는 에이전트를 반환  

    - 2-5에서 코드로 직접 하던 수동 Tool Calling 과정(요청 확인 → 도구 실행 → 결과 전달)을 대신 수행 

```python
from langchain.agents import create_agent

agent = create_agent(
    model=llm,
    tools=[web_search, get_schedule],
    system_prompt="당신은 사내 업무 어시스턴트입니다.",
)

result = agent.invoke({"messages": [{"role": "user", "content": "내일 일정 알려줘"}]})
result["messages"][-1].content   
```

- 입력과 출력 모두 `{"messages": [...]}` 형태 → `result["messages"]`에 루프 전체의 메시지가 순서대로 들어 있음  

### 4-1. ReAct 루프  

```
Reason(추론) → Act(행동) → Observe(관찰) → Reason → ... → 최종 답변
```

| 단계 | 하는 일 |
| :--- | :--- |
| Reason | LLM이 지금까지의 기록을 보고 다음에 할 일을 결정 |
| Act | 필요한 Tool을 호출 (`tool_calls`) |
| Observe | Tool 실행 결과를 확인 (`ToolMessage`) |

- `tool_calls`가 비어 있는 `AIMessage`가 나오면 루프 종료 → 그 메시지가 최종 답변  

### 4-2. `tools`  

- 사용자가 정의한 Tool 리스트를 매핑 → `bind_tools()`와 Tool 실행을 에이전트가 대신 처리  

### 4-3. `checkpointer`  

- `MemorySaver`: `thread_id` 단위로 대화 이력을 저장해 주는 체크포인터  

- 호출할 때 `config={"configurable": {"thread_id": "session-001"}}`처럼 `thread_id`를 함께 전달  

- 같은 `thread_id`면 이전 대화가 자동으로 이어지고, 다른 `thread_id`면 별개의 대화로 취급
