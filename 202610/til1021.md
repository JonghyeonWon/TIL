## 1. Docker 기본 흐름  

- Dockerfile로 DockerImage를 만들고, 이미지로 컨테이너를 띄움  

```
Dockerfile ──docker build──▶ 이미지 ──docker run──▶ 컨테이너
                              │                        │
                        docker images              docker ps
                        docker rmi                 docker rm
```

- 이미지 하나로 컨테이너를 여러 개 만들 수 있음 (클래스와 인스턴스 관계)

- 컨테이너가 참조 중인 이미지는 컨테이너를 먼저 지워야 삭제 가능  

### 1-1. 빌드 시점 vs 실행 시점  

- Dockerfile 명령어는 언제 동작하는지로 나누면 구분이 쉬움  

```
docker build → 이미지 만들기 (빌드 시점)
               FROM, WORKDIR, COPY, RUN 실행
               ※ ENV, LABEL, EXPOSE, HEALTHCHECK, CMD, ENTRYPOINT 등은 설정값으로 기록만 됨

docker run   → 컨테이너 실행 (실행 시점)
               CMD / ENTRYPOINT 실행, ENV 적용, HEALTHCHECK 주기적 실행
```

| 헷갈리는 짝 | 빌드 시점 | 실행 시점 |
| :--- | :--- | :--- |
| `RUN` vs `CMD` | `RUN npm install` → 이미지 안에 패키지 설치 | `CMD ["node", "app.js"]` → 컨테이너가 실행될 때 앱 실행 |
| `ARG` vs `ENV` | `ARG`는 빌드 중에만 존재 | `ENV`는 빌드·실행 중 모두 존재 |

## 2. docker 명령어  

### 2-1. 이미지 명령  

| 명령 | 역할 |
| :--- | :--- |
| `docker build` | Dockerfile로 이미지 만들기 |
| `docker images` | 이미지 목록 |
| `docker rmi` | 이미지 삭제 |
| `docker tag` | 같은 이미지에 태그(이름)만 하나 더 붙임 (복사 x) |
| `docker pull` / `docker push` | 레지스트리에서 받기 / 올리기 |

- `<none>` 이미지: 같은 이름으로 다시 빌드하면서 이름을 빼앗긴 이전 이미지  

- `docker push` 전에는 `docker tag`로 `사용자이름/이미지:태그` 형식으로 이름을 붙여야 함  

### 2-2. 컨테이너 명령  

| 명령 | 역할 |
| :--- | :--- |
| `docker run` | 이미지로 컨테이너를 만들고 실행 (create + start) |
| `docker ps` | 실행 중인 컨테이너 목록 (`-a`: 종료된 것까지) |
| `docker stop` / `start` / `restart` | 중지 / 기존 컨테이너 다시 시작 / 재시작 |
| `docker rm` | 컨테이너 삭제 (`-f`: 실행 중이어도 강제 삭제) |

```bash
docker run -d -p 8087:80 --name my-web my-simple-website
```

| 옵션 | 의미 |
| :--- | :--- |
| `-d` | 백그라운드 실행 (터미널 점유 x) |
| `-p 내PC포트:컨테이너포트` | 내 PC 포트를 컨테이너 포트에 연결 |
| `--name` | 컨테이너 이름 지정 |
| `-it` | 터미널을 연결해 대화형으로 실행 |

- `start`는 기존 컨테이너를 설정 그대로 다시 켜는 것 → 이미지를 다시 빌드해도 반영 안 됨  

- 코드를 고쳤다면 `rm` → `build` → `run` 순서로 새 컨테이너를 만들어야 함  

- 같은 `--name`으로 다시 `run`하면 이름 충돌 → 기존 컨테이너를 먼저 삭제  

### 2-3. logs vs exec  

| 명령 | 역할 |
| :--- | :--- |
| `docker logs` | 메인 프로세스(`CMD`/`ENTRYPOINT`)의 표준 출력·에러를 보여줌 |
| `docker exec` | 이미 실행 중인 컨테이너 안에서 추가 명령 실행 |

- `docker logs`는 메인 프로세스 출력만 보여줌 → HEALTHCHECK 스크립트처럼 따로 잠깐 실행되는 프로세스의 출력은 안 나옴 (`docker inspect`로 확인)  

- `docker run ... sh`는 새 컨테이너를 만들어 들어가는 것, `docker exec ... sh`는 이미 떠 있는 컨테이너에 들어가는 것

## 3. Dockerfile 명령어  

| 명령어 | 역할 |
| :--- | :--- |
| `FROM` | 베이스 이미지 선택 |
| `WORKDIR` | 이후 명령의 기준 폴더 지정 (없으면 자동 생성) |
| `COPY` | 내 PC의 파일을 이미지 안으로 복사 |
| `RUN` | 이미지를 만드는 중에 명령 실행 → 결과가 이미지에 저장됨 |
| `ENV` | 환경 변수 설정 |
| `EXPOSE` | 사용하는 포트를 문서화 (실제로 열지는 않음) |
| `LABEL` | 이미지에 메타정보 기록 |
| `HEALTHCHECK` | 앱 상태를 주기적으로 검사 |
| `CMD` | 컨테이너 시작 시 실행할 기본 명령 |
| `ENTRYPOINT` | 컨테이너 시작 시 실행할 고정 명령 |

### 3-1. COPY와 의존성 캐싱 패턴  

- 레이어 캐시: Docker는 입력 파일이 바뀌지 않은 단계를 캐시로 재사용, 한 단계가 바뀌면 그 아래 단계는 전부 다시 실행  

- 의존성 목록을 먼저 복사해 설치하고, 자주 바뀌는 소스 코드는 나중에 복사 → 코드만 고쳤을 때 설치 단계를 건너뜀  

```dockerfile
# ① 의존성 목록만 먼저
COPY package*.json ./  
# ② 설치 (①이 그대로면 캐시 사용) 
RUN npm install    
# ③ 소스 코드는 마지막에     
COPY . .                
```

| 언어 | ① 먼저 복사할 파일 | ② 설치 명령 |
| :--- | :--- | :--- |
| Node.js | `package*.json` | `npm install` |
| Python | `requirements.txt` | `pip install -r requirements.txt` |
| Java (Maven) | `pom.xml` | `mvn dependency:go-offline` |

### 3-2. CMD vs ENTRYPOINT  

| 구분 | `CMD` | `ENTRYPOINT` |
| :--- | :--- | :--- |
| 역할 | 기본 명령 (바꿔도 되는 값) | 고정 명령 |
| `docker run 이미지 xxx` | xxx로 통째로 교체 | xxx가 인자로 덧붙음 |
| 덮어쓰기 | 뒤에 명령만 적으면 됨 | `--entrypoint` 옵션 필요 |

```bash
# ENTRYPOINT ["java", "-jar", "app.jar"]
docker run spring-boot-app --server.port=9090   # → java -jar app.jar --server.port=9090
```

- 함께 쓰면 `ENTRYPOINT`는 고정 명령, `CMD`는 그 기본 인자가 됨  

- `CMD`가 없으면 베이스 이미지의 기본 명령이 실행됨

## 4. 멀티 스테이지 빌드  

- 빌드 도구와 실행 환경을 나눠, 최종 이미지에는 실행에 필요한 결과물만 남기는 방식  

- 컴파일러·빌드 도구·소스 코드가 최종 이미지에서 빠짐 → 용량 감소 + 공격 표면 감소  

| 문법 | 의미 |
| :--- | :--- |
| `FROM ... AS build` | 이 단계에 이름을 붙임 |
| `COPY --from=build` | 이름 붙인 단계에서 파일만 가져옴 |

```dockerfile
# 1단계: 빌드 (JDK = 컴파일러 포함)
FROM eclipse-temurin:17-jdk-alpine AS build
WORKDIR /src
COPY Main.java .
RUN javac Main.java

# 2단계: 실행 (JRE = 실행만 가능한 런타임 환경)
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app

# 1단계 결과물만 가져옴
COPY --from=build /src/*.class ./   
CMD ["java", "Main"]
```
