## `@SpringBootApplication` 

- `@SpringBootApplication`: Spring Boot 애플리케이션의 핵심 어노테이션

---

### 1.
- 프로젝트를 처음 생성하면 **Main 클래스** 위에 `@SpringBootApplication` 어노테이션이 자동으로 부착

```java
package com.example.demo; // 최상위 루트 패키지

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication // <- 프로젝트 생성 시 Main 클래스 위에 기본 탑재(base package)
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

---

### 2.

`@SpringBootApplication` = `@SpringBootConfiguration` + `@ComponentScan` + `@EnableAutoConfiguration`  

- **`@SpringBootConfiguration`**: Spring의 `@Configuration`을 대체하며, 해당 클래스가 스프링 설정 클래스임을 명시  

- **`@ComponentScan`**: 애플리케이션 내의 다양한 Component(`@Component`, `@Service`, `@Repository`, `@Controller` 등)를 스캔하여 빈으로 등록

- **`@EnableAutoConfiguration`**: 스프링 부트에서 많이 쓰이는 스프링 bean들을 자동적으로 컨테이너에 등록  

---

### 3.

Spring Boot는 구동 시 `@SpringBootApplication`에 의해 **2단계**에 걸쳐 빈을 컨테이너에 등록

#### 1단계: `@ComponentScan`

- 개발자가 직접 작성한 클래스 중 스프링 빈 어노테이션이 붙은 객체들을 찾아 컨테이너에 등록
- **스캔 범위**: `@SpringBootApplication`이 위치한 Main 클래스의 패키지를 기준점으로 잡고, 그 하위 패키지 전체를 스캔

#### 2단계: `@EnableAutoConfiguration`

- Spring Framework에서 자주 사용되는 공통 스프링 빈들을 자동으로 컨테이너에 등록

---

### 4.

- Spring Boot는 구동 시 `SpringApplication` 객체를 통해 애플리케이션 타입(`WebApplicationType`)을 판별하고, 이에 적합한 컨테이너 구현체(`ApplicationContext`)를 생성

---

#### `WebApplicationType` 종류 및 `ApplicationContext` 구현체

- `webApplicationType.SERVLET`(Blocking I/O 기반): `AnnotationConfigServletWebServerApplicationContext` 생성  

- `webApplicationType.REACTIVE`(Non-blocking 기반): `AnnotationConfigReactiveWebServerApplicationContext` 생성  

- `webApplicationType.NONE`(일반 애플리케이션): `AnnotationConfigApplicationContext` 생성

---

### 5.
Spring Boot에서 외부 설정을 주입할 때 properties 파일, 커맨드라인 인수 등의 방식이 존재

- `properties` 방식: 프로젝트 내부(`src/main/resources/`)에 설정 파일을 직접 작성하여 관리하는 방식

    - `application.properties`

    ```java
    server.port=8080
    myboot.name=SpringApp
    ```

    - `ApplicationRunner` 파일  
    ```java

    @Component
    public class AppRunner implements ApplicationRunner {
        @Value("${myboot.name}")
        private String appName;

        @Override
        public void run(ApplicationArguments args) {
            System.out.println("App Name: " + appName);
        }
    }
    ```

- **CLI 이용 방식**: 애플리케이션을 `java -jar` 명령어로 구동하는 시점에 옵션 인수로 파라미터를 전달하는 방식  

    - `-D` 옵션: JVM 자바 시스템 프로퍼티에 값을 전달하는 자바 표준 옵션
    - `--` 옵션: Spring Boot 애플리케이션(`args`)에 직접 파라미터를 전달하는 부트 전용 옵션

    ```bash
    java -Dserver.port=9090 -jar myapp.jar --myboot.name=CliApp
    ```

### 6. 

`@ConfigurationProperties`를 통한 외부 설정 주입

- `@ConfigurationProperties`: 프로퍼티 파일의 여러 설정값을 하나의 자바 객체(Class)에 묶어서 바인딩

- `@ConfigurationProperties("접두사")`를 지정하고, 필드에 대한 `Getter/Setter`를 반드시 작성  


```java

@Component
@Getter @Setter
@ConfigurationProperties("myboot") // myboot.name, myboot.age, myboot.fullName 매핑
public class MybootProperties {
    private String name;
    private int age;
    private String fullName;
}
```

- property 주입 받아 사용  

```java
@Component
public class MyRunner implements ApplicationRunner {

    @Autowired
    private MybootProperties mybootProperties;

    @Override
    public void run(ApplicationArguments args) throws Exception {
        System.out.println(mybootProperties.getName());
        System.out.println(mybootProperties.getFullName());
        System.out.println(mybootProperties.getAge());
    }
}
```
