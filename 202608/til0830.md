## 스프링 프레임워크 정리

- IoC(inversion of control): 인스턴스 생성부터 소멸까지의 인스턴스 생명주기 관리를 컨테이너가 대신 수행  
-> IoC를 지원하기 위해서 컨테이너가 필요!

- 컨테이너의 3가지 구성 요소  
    1. 설정 파일: 객체를 어떻게 만들고 연결할지 적어둔 설계도  
    2. 컨테이너: 설계도를 읽고 객체의 생명주기를 직접 관리하는 주체  
    3. 빈: 컨테이너가 생성, 관리하는 실제 객체  
---
### 1. 설정 파일
- 컨테이너가 어떤 객체를 만들고, 객체 간 의존성을 어떻게 연결해야 하는지 정의한 파일  
- 개발자가 직접 `new` 키워드로 객체 인스턴스를 생성하지 않고, 객체 생성 방식과 관계만 여기에 정의  
- 구현 방식: XML 파일, `@Configuration`을 포함한 Config 클래스  
---
#### 설정 파일 구현 방식 1 (XML에 모든 bean 선언)

- **`<property>` 태그 (Setter injection)**
  - 객체의 Setter 메서드를 호출하여 의존성이나 값을 주입
  - `name` 속성에는 필드명, `ref` 속성에는 주입할 다른 Bean의 ID, `value` 속성에는 기본 값을 지정

- **`<constructor-arg>` 태그 (constructor injection)**
  - 객체의 생성자를 호출하여 의존성이나 값을 주입
  - `ref`나 `value` 속성을 사용하며, 필요 시 `index`나 `type` 속성으로 생성자 파라미터 순서를 명시 가능  

```xml
<beans xmlns="[http://www.springframework.org/schema/beans](http://www.springframework.org/schema/beans)" ...>
    <!-- Setter 주입 (property) -->
    <bean id="memberRepository" class="com.example.MemoryMemberRepository">
        <property name="maxSize" value="100" />
    </bean>
    <!-- 생성자 주입 (constructor-arg) -->
    <bean id="memberService" class="com.example.MemberServiceImpl">
    <constructor-arg index="0" ref="memberRepository" />
    <constructor-arg index="1" type="int" value="100" />
</bean>

</beans>
```

```java
public class MemoryMemberRepository {
    
    private int maxSize;

    public MemoryMemberRepository() {
    }

    // <property name="maxSize" value="100" /> 에 대응하는 Setter 메소드
    public void setMaxSize(int maxSize) {
        this.maxSize = maxSize;
    }

    public int getMaxSize() {
        return maxSize;
    }
}

public class MemberServiceImpl implements MemberService {

    private final MemoryMemberRepository memberRepository;
    private final int maxUsers;

    // <constructor-arg index="0" ref="memberRepository" />
    // <constructor-arg index="1" type="int" value="100" /> 에 대응하는 생성자
    public MemberServiceImpl(MemoryMemberRepository memberRepository, int maxUsers) {
        this.memberRepository = memberRepository;
        this.maxUsers = maxUsers;
    }
}
```

#### 설정 파일 구현 방식 2 (XML + @Component)

- XML 파일 내에 `<context:component-scan>` 태그를 선언하여 특정 패키지를 지정하고, 해당 패키지 하위의 클래스에 붙은 어노테이션(`@Component`, `@Service`, `@Repository`, `@Controller` 등)을 스캔하여 빈으로 자동 등록하는 방식

- **`<context:component-scan>`**: XML에서 스캔할 기본 패키지(`base-package`)를 지정  
- XML에 일일이 `<bean>` 태그를 작성하지 않고, 자바 클래스 상단에 `@Component` 계열 어노테이션을 붙여 빈 대상으로 지정  

```xml
<beans xmlns="[http://www.springframework.org/schema/beans](http://www.springframework.org/schema/beans)" />

    <!-- base-package 하위의 @Component 어노테이션을 탐색하여 자동 빈 등록 -->
    <context:component-scan base-package="com.example" />

</beans>
```

```java
// 클래스에 직접 어노테이션을 적용하여 빈으로 등록
@Repository
public class MemoryMemberRepository {
    private int maxSize = 100;
}

@Service
public class MemberServiceImpl implements MemberService {

    private final MemoryMemberRepository memberRepository;

    @Autowired
    public MemberServiceImpl(MemoryMemberRepository memberRepository) {
        this.memberRepository = memberRepository;
    }
}
```

#### 설정 파일 구현 방식 3 (단일 config 클래스 파일)  
- XML 파일을 전혀 사용하지 않고, 자바 클래스에 `@Configuration`을 붙여 완전한 설정 파일로 사용하는 방식
- 외부 패키지 스캔 방식 대신 메서드에 `@Bean`을 붙여 애플리케이션에 필요한 모든 빈과 의존관계를 수동으로 직접 명시
- `@Configuration`: 해당 자바 클래스가 스프링 설정 파일 역할을 함을 선언  

- `@Bean`: 메서드 상단에 붙여 메서드가 반환하는 객체를 스프링 빈으로 등록

- 의존성 주입: @Bean 메서드 내부에서 다른 @Bean 메서드를 직접 호출하거나, 메서드 파라미터로 주입받아 의존관계를 연결  

```java
@Configuration
public class AppConfig {

    // MemoryMemberRepository 빈 수동 등록
    @Bean
    public MemoryMemberRepository memberRepository() {
        MemoryMemberRepository repository = new MemoryMemberRepository();
        repository.setMaxSize(100);
        return repository;
    }

    // MemberService 빈 수동 등록 및 생성자 주입
    @Bean
    public MemberService memberService() {
        // memberRepository() 메서드를 호출하여 의존성을 주입 
        return new MemberServiceImpl(memberRepository(), 100);
    }
}
```

### 2. 컨테이너 
- 작성된 설정 파일(XML, Java Config 등)을 읽어 들여 객체의 생성, 의존성 주입(DI), 초기화, 소멸까지의 전체 생명주기를 직접 관리하는 주체  
- 개발자 대신 객체의 제어권을 넘겨받아 **IoC**를 실제로 구현  

#### 주요 컨테이너 인터페이스
1. **`BeanFactory`**
   - 스프링 컨테이너의 최상위 인터페이스
   - 빈을 등록, 생성, 조회하는 기본 기능을 제공
   - **지연 로딩(Lazy Loading)**: 컨테이너 구동 시점에는 빈의 메타데이터만 생성해 두고, 실제 객체 인스턴스는 `getBean()`이 최초로 호출되는 시점에 생성  

2. **`ApplicationContext`**
   - `BeanFactory`를 상속받아 기능을 확장한 컨테이너
   - **조기 로딩(Eager Loading)**: 애플리케이션 구동 시점에 모든 싱글톤 빈을 미리 생성하고 의존성을 주입하므로 `getBean()` 호출 시에는 이미 만들어진 인스턴스를 즉시 반환

`ApplicationContext`는 인터페이스이므로, 설정 정보의 형식이나 애플리케이션 환경에 따라 다양한 구현 클래스 제공  

---

### 3. 빈 
- 스프링 컨테이너에 의해 생성되고, 의존성이 주입되며, 생명주기가 관리되는 객체
- 개발자가 일반적인 `new` 키워드로 직접 생성한 객체는 스프링 빈이 아니며, 컨테이너가 제어권을 가지고 관리하는 객체가 빈

#### 빈의 생명주기
스프링 컨테이너가 관리하는 빈은 다음과 같은 순서로 생명주기가 진행됩니다.

> **스프링 컨테이너 생성** -> **스프링 빈 생성** -> **의존관계 주입** -> **초기화 콜백** -> **사용** -> **소멸 전 콜백** -> **스프링 종료**

- **초기화/소멸 콜백 처리 방법**: `@PostConstruct` / `@PreDestroy` 어노테이션 사용 

```java
public class NetworkClient {

    public NetworkClient() {
        System.out.println("1. 생성자 호출 (빈 생성)");
    }

    @PostConstruct
    public void init() {
        System.out.println("2. 초기화 콜백 (의존관계 주입 완료 후 실행)");
    }

    @PreDestroy
    public void close() {
        System.out.println("3. 소멸 전 콜백 (컨테이너 종료 직전 실행)");
    }
}
```
```java
@Configuration
public class AppConfig {

    @Bean
    public NetworkClient networkClient() {
        // 스프링 컨테이너가 객체를 빈으로 등록하면서 @PostConstruct, @PreDestroy를 감지하여 실행
        return new NetworkClient();
    }
}
```

#### 빈 스코프 

- 스프링 빈이 존재하고 적용되는 범위를 의미하며, 빈이 생성되어 소멸하기까지의 생명주기와 관리 주체를 결정

#### 1. 싱글톤(Singleton) - 기본값
- 스프링 컨테이너의 시작부터 종료까지 단 하나만 생성되어 애플리케이션 전체에서 공유되는 스코프

#### 2. 프로토타입 (Prototype)
- 컨테이너에 빈을 요청(getBean())할 때마다 매번 새로운 인스턴스를 생성하여 반환하는 스코프
- 스프링 컨테이너는 빈의 생성, 의존관계 주입, 초기화(@PostConstruct)까지만 관여
- 반환된 이후의 관리 책임은 클라이언트에게 넘어가므로, 소멸 콜백(@PreDestroy)이 실행되지 않음
