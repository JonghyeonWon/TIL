## Bean 등록 메타정보 구성 전략  

### 전략 1. XML 단독 사용  
- 모든 bean을 명시적으로 xml에 등록하는 방법  
- 생성되는 모든 bean을 xml에서 확인할 수 있지만, bean의 개수가 많아지면 단독 xml 파일로 관리하기 힘듦  
---
### 전략 2. 어노테이션(Annotation)과 XML 설정 혼용  
- bean으로 사용될 클래스에 `@Component` 어노테이션을 부여하면 `빈 스캐닝`을 통해 어노테이션이 선언된 클래스를 자동으로 찾아서 bean으로 등록  
- xml 파일의 크기는 줄어들 수 있지만, bean들을 한번에 관리하기는 어려움  
---
- Bean 등록 Annotation  
    - `@Component`: xml의 `<bean>` 태그와 동일한 역할  
    - `@Repository`: 영속성을 가지는 속성을 가진 클래스  
    - `@Service`: 비즈니스 로직을 가지는 클래스  
    - `@Controller`: 요청과 응답을 처리하는 클래스  
---
- Bean 의존관계 설정 Annotation  
    - `@Autowired`: 의존하는 객체를 자동으로 주입해주는 어노테이션  
        - 의존하는 객체를 주입할 때 주로 `Type`을 이용  
        - xml의 `<property>`, `<constructor-arg>` 태그와 동일한 역할  
    - `@Resource`: autowired와 비슷하지만 의존하는 객체를 주입할 때 **이름**으로 연결  
    - `@Value`: 값을 주입할 때 사용하는 어노테이션  
    - `@Qualifier`: 주로 `@Autowired`와 함께 사용되어, 특정 bean을 지정해야할 때 사용  

- `@Component`로 bean을 등록하고, `@Autowired`로 의존관계를 주입받는 어노테이션을 클래스에서 선언했다면 xml에서 이를 scan하도록 아래와 같이 설정
```xml
<context:component-scan base-package="myspring.di.annot" />
```
---
### 전략 3. 어노테이션 설정 단독 사용  
- `@Configuration` 어노테이션이 붙은 클래스가 xml 파일의 역할을 대신함  
- `@Bean` 어노테이션은 주로 객체 생성자 메서드에 붙어 새로운 빈 객체를 제공할 때 사용됨
    - 메서드의 이름을 bean 식별값으로 사용
