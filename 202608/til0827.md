## IoC(inversion of control)
프로그램의 제어 흐름을 직접 제어하는 것이 아니라 외부에서 관리하는 것  

- 프레임워크 vs 라이브러리  
    - 외부 주체가 내가 작성한 코드를 제어하고, 대신 실행하면 프레임워크  
    - 내가 작성한 코드가 직접 제어 흐름을 담당하면 라이브러리  
---
## DI(dependency injection)
- 정적 의존 관계: 애플리케이션을 실행하지 않아도 의존 관계를 분석 가능  
- 동적 의존 관계: 애플리케이션 실행 시점에 실제 생성된 객체 인스턴스의 참조가 연결된 의존 관계  

- **의존관계 주입**: 애플리케이션 실행 시점에 외부에서 실제 구현 객체를 생성하고 클라이언트에 전달해서 클라이언트와 서버의 실제 의존관계가 연결되는 것  
    - 클라이언트 코드를 변경하지 않고 호출하는 대상의 타입 인스턴스 변경 가능  
    - 정적 의존 관계를 변경하지 않고 동적 의존 관계를 쉽게 변경 가능  
---
## 컨테이너
객체를 생성하고 관리하면서 의존관계를 연결해 주는 주체  
```java
ApplicationContext ac = new AnnotationConfigApplicationContext(AppConfig.class);
```
- `ApplicationContext`는 인터페이스이자 컨테이너  
- 컨테이너는 XML 기반으로 만들 수 있고, 애노테이션 기반으로도 가능  
- `AnnotationConfigApplicationContext`는 `ApplicationContext`의 구현체 중 하나  

### 컨테이너 생성 과정  
1. 스프링 컨테이너 생성
    - 구현 객체를 호출할 때 매개변수로 구성 정보를 지정해야함  
2. 스프링 빈 등록  
    - 컨테이너는 정보를 활용하여 빈을 등록  
3. 빈 생성, 빈 의존관계 설정
    - 설정 정보를 참고하여 의존관계 주입
