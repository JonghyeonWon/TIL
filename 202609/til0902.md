## 1. `EntityManager`

- `EntityManager`: 엔티티의 db 접근 및 CRUD 작업을 처리하는 객체  
- 트랜잭션이 들어올 때마다 `EntityManagerFactory`를 통해 새 객체가 생성되며, db의 커넥션 풀을 이용하여 db에 접근  

- `EntityManagerFactory`: 요청 시마다 `EntityManager`를 생성하는 팩토리 역할  
- 애플리케이션이 실행될 때 하나만 생성되며, 앱 전체가 공유하여 사용  
- db의 커넥션 풀을 관리  

- 이미지 삽입 필요

---

## 2. 트랜잭션  

- JPA의 데이터 처리의 기본 단위는 `transaction`  
- `transaction`: 하나의 논리적 작업 단위를 이루는 db 조작의 집합으로, ACID 원칙을 보장  

    - Atomicity(원자성): 트랜잭션 내의 모든 작업은 모두 성공(Commit)하거나 모두 실패(Rollback)  

    - Consistency(일관성): 트랜잭션 실행 전후의 데이터베이스는 일관된 상태를 유지  

    - Isolation(격리성): 동시에 실행되는 트랜잭션들이 서로 영향을 주지 않도록 함  

    - Durability(영속성): 성공적으로 완료된 트랜잭션의 결과는 시스템 장애가 발생하더라도 영구적으로 반영되어야 함  

- `Spring data JPA`는 `@Transactional`을 이용해 트랜잭션 관리를 자동화  
- 모든 과정이 성공하면 `commit`, 하나라도 실패하면 `rollback` 발생  
- `entitymanager`는 `dirty check`를 하므로 데이터의 변경을 자동으로 감지하고 반영  

## 3. 영속성 컨텍스트  

영속성 컨텍스트: `entitymanager`를 통해 접근할 수 있는 논리적 공간으로, `entitymanager`와 대응되는 논리적인 개념  
- 영속성 컨텍스트 내부에는 `JPA(@Transactional)`가 관리하는 `entity`가 존재  

### `entity` 생명 주기

- 이미지 삽입 필요

- `@Transactional`을 사용하면 위의 객체 관리 과정이 자동화됨  
- Dirty checking, 캐시, 쓰기 지연 등의 추가적인 이점 존재

## 4. `REST(Representational State Transfer)`

- `REST`: http 프로토콜의 우수성을 활용하여 디자인된 분산 시스템 아키텍쳐  
- `RESTful`: REST 아키텍쳐 원칙을 모두 만족하는 API  

- REST 구성 요소
    - 자원: URI(uniform resource identifier)로 표현(명사 사용 권장)  
    - 행위: http method(`GET`, `POST`, `PUT`, `DELETE`)로 표현  

- REST 제약 조건
    - Client - Server 구조: 클라이언트와 서버의 분리  
    - Stateless: 상태 정보를 저장하지 않음  
    - Cache: HTTP의 캐시 기능 활용  
    - Layered System: REST 서버를 계층 구조로 구성  
    - Uniform Interface: 자원의 유일 식별, HTTP Method로 표현, 메시지의 self-descriptive 성질 포함, 하이퍼링크를 통한 앱 상태 전이

## 5. `@RestController` & JSON 처리

- `@RestController`: `@Controller` + `@ResponseBody`가 합쳐진 애노테이션
    - View를 반환하지 않고, HTTP 응답 본문(Body)에 직접 데이터를 JSON 형태로 반환

- **Jackson 라이브러리**: Java 객체와 JSON 간의 변환을 담당

    - **직렬화 (Serialization)**: Java Object ➔ JSON (`@ResponseBody` 응답 시)
    - **역직렬화 (Deserialization)**: JSON ➔ Java Object (`@RequestBody` 요청 시)

- **`HttpMessageConverter`**: HTTP 요청/응답 메시지와 객체를 상호 변환하는 인터페이스로, `Content-type`에 맞춰 적절한 Converter가 자동 선택됨

- `Jackson`은 `HttpMessageConverter`를 구현한 구현체 중 하나로, `Jackson`이 없어도 기본 문자열/숫자에 대한 처리는 가능하지만 `Object`를 반환하려고 하면 converter가 없기 때문에 에러가 발생  

--- 

## 6. 예외 처리 (`@RestControllerAdvice`)

- **`@RestControllerAdvice`**: `@ControllerAdvice` + `@ResponseBody`가 합쳐진 기능
    - 애플리케이션 전역에서 발생하는 예외를 한곳에서 모아 처리(AOP 기반)하는 클래스 선언

- **`@ExceptionHandler`**: 특정 예외(예: `BusinessException`)가 발생했을 때 이를 캐치하여 처리할 메서드를 지정

## 7. DTO (Data Transfer Object) 사용 이유

- **Entity 보호 및 분리**: DB 테이블과 직접 매핑되는 Entity를 외부에 직접 노출하지 않고, API 요청/응답 스펙에 맞춘 객체를 따로 분리하기 위함

- **순환 참조 방지**: Entity 간 양방향 연관관계가 있을 때 JSON 직렬화 과정에서 발생하는 무한 루프(순환 참조) 오류를 차단

- **필요한 데이터만 전달**: 요청/응답에 불필요한 정보(예: 비밀번호, 생성일자 등)를 숨기거나 필요한 데이터만 선별하여 전달 가능

- **유효성 검사(Validation) 용이**: API 스펙마다 달라지는 입력값 검증 로직(`@NotBlank`, `@NotNull` 등)을 DTO 단에서 깔끔하게 처리 가능
