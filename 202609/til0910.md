## 1. DOM  

- `DOM(document object model)`: HTML 문서를 브라우저가 이해하고 조작할 수 있는 객체의 트리 구조로 표현한 인터페이스  
- HTML 문서를 읽고 각 태그, 속성들이 노드가 됨  
- `JavaScript`는 HTML 파일에 접근하는 게 아니라 `DOM`에 접근  

- `document.getElementById()`, `document.querySelectorAll()` 등으로 각 요소를 쉽게 탐색 가능  
- `FormData` 객체를 이용하면 name 속성을 key로 하여 값을 쉽게 꺼낼 수 있음  

- `DOMContentLoaded`: HTML 문서를 다 읽고 화면 구조가 완성된 이후에 실행하라는 명령  

- `addEventListener`: 대상 요소에서 특정 이벤트가 일어나면 그 때의 지정한 함수를 실행하라고 미리 등록해둘 수 있는 메서드

- `e.preventDefault()`: form 태그의 기본 동작인 "값을 서버에 보내고 페이지를 새로고침"하는 것을 막고 JavaScript로 직접 처리할 것임을 명시  

```javascript
  document.addEventListener("DOMContentLoaded", function () {
    loadStudents();
  });
 
  studentForm.addEventListener("submit", function (e) {
    e.preventDefault();
  });

```

## 2. 비동기 처리와 fetch  

- 비동기 방식: 실행 시간이 오래 걸리는 작업을 기다리는 동안 다른 작업을 계속 수행할 수 있게 하는 방식  

- `fetch()`: 브라우저에서 서버로 HTTP 요청을 보내고 응답을 받아올 수 있도록 하는 함수  
    - 작업 완료시 결과를 반환하겠다는 `Promise` 객체를 반환  
    - `then()`을 통해 결과를 받은 후 할 행동을 미리 정의 가능  

- `async / await`: `then()` 체인을 사용하는 대신, 마치 동기식 코드처럼 더 직관적으로 비동기 로직을 작성 가능  
    - `async`: 비동기 작업을 수행함을 명시  
    - `await`: `Promise`가 완료될 때까지 코드 실행을 대기한 후 결과 값을 가져옴

## 3. 1:N 연관관계  

- 하나에 여러 개가 속하는 관계로, 외래 키를 가지고 있는 N쪽이 연관관계의 주인이 됨  

- `@ManyToOne`: N쪽 엔티티의 참조 필드에 설정하며, 기본 `FetchType`이 `EAGER`이므로 `FetchType.LAZY`로 지정이 필요  

- `@OneToMany`: 비주인인 엔티티의 필드에 설정하며, 기본 `FetchType`이 `LAZY`
    - `mappedBy` 옵션으로 주인 엔티티의 필드명을 지정해야함

## 4. N+1 문제와 성능 최적화  

- `N+1 문제`: 1번의 쿼리로 N개의 데이터를 읽은 뒤, 지연 로딩된 연관 엔티티를 조회할 때마다 N번의 추가 SQL이 실행되는 현상  

- `Fetch Join(LEFT JOIN FETCH)`: JPQL에서 연관 엔티티를 1번의 SQL로 함께 로딩하도록 처리할 수 있게 함  
    - `INNER JOIN` 대신 `LEFT JOIN FETCH`를 사용하여 연관 데이터가 없는 개체도 조회 결과에서 누락되지 않도록 방지  

- `Projection`: DB에서 원하는 특정 컬럼들만 골라서 가져오는 기술  

    - 필요한 연관 컬럼이나 COUNT() 같은 집계 결과를 1번의 쿼리로 가져와 N+1 문제 회피 가능  

    - 조회된 데이터가 Entity가 아니므로 영속성 컨텍스트가 관리하지 않음 -> 변경 감지용 스냅샷을 만들지 않아 메모리를 적게 사용함
