## 1. CORS 개념 이해

- Origin: `URI 스키마` + `Hostname` + `Port` 의 조합  
    - ex `http://localhost:8080`

- **SOP (Same-Origin Policy)**: 브라우저가 같은 Origin으로만 AJAX 요청을 보낼 수 있도록 제한하는 정책  

- **CORS (Cross-Origin Resource Sharing)**: 서로 다른 Origin 간에 리소스를 공유할 수 있도록 허용하는 메커니즘  

---

## 2. Spring Boot에서 CORS 설정 방법

### 방법 1. `@CrossOrigin` 어노테이션 (개별 설정)

- 특정 `Controller`나 `Method` 단위로 허용할 Origin을 지정할 때 사용  

```java
@RestController
@CrossOrigin(origins = "http://localhost:18080")    // 이 origin에 대한 resource share 허용
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello World";
    }
}
```

### 방법 2. `WebMvcConfigurer` 활용 (전역 설정)  

- 프로젝트 전체에 대해 `CORS` 정책을 적용할 때 사용  

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**") // 모든 경로에 대해 적용
                .allowedOrigins("http://localhost:3000") // 요청을 허용할 Origin
                .allowedMethods("*"); // 허용할 HTTP Method (GET, POST, PUT, DELETE 등)
    }
}
```

## 3. Spring Security  

- 웹 시큐리티, 메서드 시큐리티, 다양한 인증 방식(Basic, Form, OAuth, LDAP 등) 지원  

- `spring-boot-starter-security`의존성 추가 시 모든 요청에 대해 인증을 요구  

### Spring Security 인증 아키텍처 (Form Login 흐름)

1. **로그인 요청**: 사용자가 Form을 통해 아이디/패스워드 제출  

2. **Filter 인터셉트**: `UsernamePasswordAuthenticationFilter`가 요청을 가로채 `UsernamePasswordAuthenticationToken`(인증 전 객체) 생성  

3. **Manager 위임**: Token을 `AuthenticationManager` (구현체: `ProviderManager`)에게 전달  

4. **Provider 전달**: `AuthenticationManager`는 적절한 `AuthenticationProvider`에게 인증 처리(토큰) 위임  

5. **사용자 정보 조회**: `UserDetailsService`가 DB/메모리에서 사용자 정보를 조회하여 `UserDetails` 객체로 반환  

6. **인증 검증**: `AuthenticationProvider`가 입력된 비밀번호와 `UserDetails`의 암호화된 비밀번호를 비교/검증  

7. **성공 처리**: 인증이 완료된 `Authentication` 객체를 `SecurityContextHolder`에 저장하고 `AuthenticationSuccessHandler` 실행  

---

### 사용자 인증 설정 방식

### 3.1. `application.properties` 이용 (단일 사용자)

```properties
spring.security.user.name=boot3
spring.security.user.password=test1234
```

### 3.2 메모리 기반 사용자 설정(`InMemoryUserDetailsManager`)  

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public UserDetailsService userDetailsService(PasswordEncoder encoder) {
        UserDetails admin = User.withUsername("adminboot")
                .password(encoder.encode("pwd1"))
                .roles("ADMIN")
                .build();

        UserDetails user = User.withUsername("userboot")
                .password(encoder.encode("pwd2"))
                .roles("USER")
                .build();

        return new InMemoryUserDetailsManager(admin, user);
    }
}
```

### 3.3 db와 세큐리티 연결  

- DB와 세큐리티를 연결하려면 `Entity`, `Repository`외 3개의 컴포넌트가 추가로 필요  

1. **`UserDetails`(일종의 DTO)**
   - DB의 `User` Entity를 그대로 쓰지 않고, Security가 알아들을 수 있는 표준 규격(아이디, 암호화된 비밀번호, `GrantedAuthority` 권한 목록)으로 변환해 주는 어댑터/DTO 역할  

2. **`UserDetailsService`(DB 조회용 컴포넌트)**
   - 기존 엔티티 `User`에서 `UserDetails`로 만들어 반환하는 역할  

3. **`DaoAuthenticationProvider` (자동 검증 및 비밀번호 비교)**
   - `UserDetailsService`가 넘겨준 DB 정보와 사용자가 입력한 패스워드를 받아 **`PasswordEncoder`로 해시 값을 자동 비교**하고 인증을 마무리

## 4. `Filter`, `FilterChain`  

- Spring Security는 기본적으로 **Servlet Filter 기반**으로 작동하며, 요청(Request)이 `DispatcherServlet(Controller)`에 도달하기 전에 보안 검사를 수행합니다.

### 4.1.  

- **Filter (필터)**
  * 컨테이너 수준에서 요청/응답을 가로채서 처리하는 컴포넌트  
  * Authentication, Authorization, CORS, CSRF, 세션 관리 등 각기 다른 보안 역할을 전담하는 여러 필터들이 존재  

- **SecurityFilterChain (시큐리티 필터 체인)**
  * 여러 개(보통 10~15개 이상)의 `Security Filter`들이 지정된 순서대로 연결된 사슬(Chain) 구조  

  * 클라이언트 요청이 들어오면 필터 체인을 순차적으로 통과하며, 중간에 인증/인가 실패 시 체인이 중단되고 예외 처리기(AuthenticationEntryPoint 등)로 이동

### 4.2. Servlet Container와 Spring Container의 연결 구조

스프링 시큐리티를 이해할 때 가장 먼저 부딪히는 어려움은 **"Tomcat(서블릿) 영역의 기술인 Filter가 어떻게 Spring 영역의 Bean(객체)들을 가져다 써서 인증을 처리하는가?"**입니다.

두 영역은 관리 주체가 완전히 다르기 때문에 이를 연결해 주는 특별한 다리 역할이 필요합니다.

#### 1. 핵심 용어 쉬운 개념 정리

* **서블릿 컨테이너 (Servlet Container / 예: Tomcat)**
  * 자바 웹 애플리케이션을 실행하고 `Servlet`과 `Filter`의 생성, 실행, 소멸을 관리하는 외부 엔진  

  * 스프링 내부 사정(스프링 Bean, `@Autowired` 등)을 전혀 모름  

* **스프링 컨테이너 (Spring Container / ApplicationContext)**
  * 우리가 작성한 `@Component`, `@Service`, `@Bean` 객체들을 관리하는 스프링 내부 공간  

* **DelegatingFilterProxy (위임 대리인 필터)**
  * 서블릿 컨테이너(Tomcat)에 등록되는 **표준 서블릿 필터**  

  * 자기 스스로 보안 로직을 수행하지 않고, 요청을 가로채서 **스프링 컨테이너 안에 있는 진짜 보안 필터(`FilterChainProxy`)에게 처리를 위임(Delegate)**하는 다리(Bridge) 역할  

* **FilterChainProxy (시큐리티 총괄 관리자)**
  * 스프링 컨테이너 내부에서 Bean으로 관리되는 시큐리티의 핵심 객체  
  * 설정된 여러 개의 `SecurityFilterChain` 목록을 들고 있으면서, 현재 요청에 맞는 필터 체인을 찾아 순서대로 보안 검사를 지시
