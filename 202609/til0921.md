## 1. React Router  

- 멀티 페이지 웹사이트와 달리 `SPA(Single Page Application)`는 하나의 HTML 위에서 JavaScript를 통해 주소(URL)에 따라 필요한 컴포넌트만 바꿔 끼워 부드러운 화면 전환을 제공하므로 라우터가 필수적  

### 주요 라우터 컴포넌트  

- `<BrowserRouter>`: 브라우저의 현재 주소와 React 앱을 동기화해 주는 최상위 컨테이너  

- `<Routes>`, `<Route>`: 현재 URL 경로와 매칭되는 컴포넌트를 렌더링하는 조건부 라우팅 제어  

- `<Link>`, `<NavLink>`: 페이지 전체를 새로고침하지 않고 브라우저 주소만 변경하여 SPA의 특성을 유지하면서 페이지를 이동  

### 주요 Hook의 역할  

- `useParams`: URL 경로에 포함된 동적 파라미터(예: `/students/:id`)를 객체 형태로 추출  

- `useLocation`: 현재 URL의 경로, 쿼리 스트링 등 현재 위치 정보를 담은 객체를 반환  

- `useNavigate`: 코드를 통해 페이지를 이동(예: 로그인 후 리다이렉트, 버튼 클릭 시 이동)

## 2. Zustand  

- **Props Drilling**:

    - 부모 컴포넌트에서 하위 컴포넌트로 데이터를 전달할 때, 중간에 있는 여러 컴포넌트를 거쳐 props를 계속 내려주어야 하는 현상  

    - 컴포넌트 구조가 깊어질수록 코드가 복잡해지고 유지보수가 어려워지는 문제가 발생  


- 컴포넌트 계층 구조가 깊어지면 `props drilling` 문제가 발생하므로, 전역에서 상태를 효율적으로 관리하고 필요한 컴포넌트만 리렌더링하기 위해 상태 관리 라이브러리가 필요  

- `Zustand`: Redux에 비해 보일러플레이트 코드가 적고 가벼우며, React Hooks 기반으로 직관적인 전역 상태 관리를 제공  

### Store 생성과 핵심 함수  

- `create`: 상태 변수와 액션 함수를 포함하는 `Store`를 정의  

- `set`: 현재 상태를 불변성을 유지하며 업데이트하는 역할  

- `get`: Store 내부에서 현재 상태 변수들의 값이나 다른 상태를 참조할 때 사용

## 3. 1:N 연관관계 매핑

- **1:N 연관관계**: 학과 하나에 여러 명의 학생이 속하는 구조로, 관계의 N 쪽인 `students` 테이블이 외래키(`department_id`)를 가지고, 외래키를 가진 N 쪽이 연관관계의 주인이 됨  

### JPA 성능 최적화: N+1 문제와 프로젝션(Projection)

- **N+1 문제 해결**: 연관된 엔티티를 조회할 때 추가 쿼리가 대량으로 발생하는 N+1 문제를 해결하기 위해 `LEFT JOIN FETCH`를 사용하거나 글로벌 설정으로 `hibernate.default_batch_fetch_size`를 적용할 수 있음  

- **인터페이스 기반 프로젝션**:

- 엔티티 전체를 조회하는 대신 필요한 컬럼이나 집계 함수 결과(예: 학과별 학생 수 `COUNT(s)`)만 골라서 조회하는 방식  

- 영속성 컨텍스트가 관리하지 않는 조회 전용 방식으로, 불필요한 메모리 낭비를 줄이고 쿼리 최적화 가능
