## 1. Spring Web MVC 정적 리소스  

- 정적 리소스 자동 매핑을 지원하는 기본 위치
    - `classpath:/static`  
    - `classpath:/public`  
    - `classpath:/resources/`  
    - `classpath:/META-INF/resources/`  

- 이 위치에 저장되는 정적 리소스들은 별다른 설정 없이 매핑이 가능  

---

## 2. 정적 리소스 매핑 커스터마이징  

- `WebMvcConfigurer` 인터페이스 아래의 `addResourceHandlers` 메서드를 오버라이딩함으로써 기본 정적 리소스 설정을 유지하면서, 새로운 리소스 매핑 설정이 가능  

`WebConfig.java`

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // 리소스와 매핑될 경로 설정(/mobile/..)
        registry.addResourceHandler("/mobile/**")   
        // 실제 빌드 되었을 때 Maven 기준 target/class 아래의 mobile 폴더 위치
        .addResourceLocations("classpath:/mobile/")
        .setCachePeriod(20);
    }
}
```
- `/mobile/**` 패턴으로 URL이 들어오면 `classpath` 경로에서 파일을 찾아 응답한다는 매핑 규칙(여기서는 `ResourceHandler`)을 등록

## 3. Thymeleaf

- HTML 문법을 유지하면서 서버쪽 로직을 수행하고 적용시킬 수 있는 HTML 템플릿 엔진  

- 서버를 거치지 않고 브라우저에서 직접 HTML 파일을 열어도 깨짐 없이 확인이 가능  

- Thymeleaf 문법을 사용하려면 HTML 파일 상단에 다음의 네임스페이스 선언 필요  

```html
    <html xmlns:th="http://www.thymeleaf.org"> 
```

- 템플릿 파일 기본 위치: `src/main/resources/templates/`

### JSP vs Thymeleaf 비교

| 구분 | JSP | Thymeleaf |
| :--- | :--- | :--- |
| **템플릿 방식** | 서블릿(Java Code)으로 변환되어 실행 | Natural Template (HTML 문법 그대로 유지) |
| **브라우저 직접 열기** | 불가 (서버 실행 없이 열면 태그 깨짐) | 가능 (서버 없이도 브라우저에서 디자인 확인 가능) |
| **패키징 제약** | WAR 패키징 필수 (`java -jar` 실행 제약) | JAR 패키징 지원 (독립 실행 가능) |

- **Spring Boot에서 JSP 사용을 권장하지 않는 이유**
    - JAR 패키징으로 빌드 시 JSP가 정상 동작하지 않음  
    - HTML 구조와 자바 코드가 섞여 유지보수가 어려움  

### Thymeleaf 주요 표현식 (Expressions)

| 표현식 | 이름 | 설명 | 사용 예시 |
| :--- | :--- | :--- | :--- |
| **`${...}`** | Variable Expressions | Model에 담긴 변수 값을 참조하여 출력 | `<span th:text="${name}"></span>` |
| **`*{...}`** | Selection Variable Expressions | 상위 태그에 `th:object`로 지정된 객체의 필드값을 선택적으로 참조 | `<input th:field="*{email}">` |
| **`#{...}`** | Message Expressions | `messages.properties` 등 설정 파일에 미리 정의된 메시지 출력 | `<p th:text="#{welcome.message}"></p>` |
| **`@{...}`** | Link URL Expressions | 애플리케이션 컨텍스트 경로를 포함한 서버 URL을 다양하게 표현 | `<a th:href="@{/signup}">회원가입</a>` |

## 4. controller - HTML - Thymeleaf 간 동작 흐름  

#### 1. 역할 분담

- **Controller (Java)**: 요청을 받아 비즈니스 로직을 처리하고, 화면에 출력할 **데이터(Model)**를 준비하여 전달할 **HTML 파일 이름(View Name)**을 반환  

- **Model (Java)**: `Controller`에서 `View(HTML)`로 데이터를 전달하는 **데이터 바구니** 역할(`key-value` 형태)  

- **HTML**: 화면의 전체적인 **뼈대(UI)**를 제공  

- **Thymeleaf**: 서버 실행 시 HTML 내부의 `th:*` 태그를 해석하여 Model에 담긴 데이터를 HTML 뼈대에 렌더링한 후, **순수 HTML**로 변환하여 브라우저에 전달  

---

#### 2. 데이터 흐름 한눈에 보기

1. `/thymeleaf` 에 대한 GET 요청   
2. return을 통해 `leaf.html` 반환  
3. `leaf.html`에서 `model`의 정보를 사용하여 렌더링  

`UserController.java` (Controller)

```java
@Controller
public class UserController {

    @GetMapping("/thymeleaf")
    public String leaf(Model model) {
        // Model 바구니에 "name"이라는 키로 "basic" 값을 저장
        model.addAttribute("name", "basic");
        
        // src/main/resources/templates/leaf.html 파일을 렌더링하도록 지정
        return "leaf"; 
    }
}
```

`leaf.html` (View Template)

```HTML
<!DOCTYPE html>
<html xmlns:th="[http://www.thymeleaf.org](http://www.thymeleaf.org)">
<head>
    <meta charset="UTF-8">
    <title>Spring Boot Thymeleaf</title>
</head>
<body>
    <!-- Thymeleaf가 Model의 "name" 키값을 조회하여 <h1>basic</h1>으로 변환 -->
    <h1 th:text="${name}">기본값(서버 안 거칠 때 출력)</h1>
</body>
</html>
```

## 5. Validation  

- **Java Bean Validation**: 검증 로직을 도메인 모델(Entity/DTO)에 어노테이션으로 부여하여 데이터 유효성을 검사하는 방식

---

### 주요 검증 어노테이션 (`User.java`)

```java
@Entity
public class User {
    @NotNull(message = "Name is mandatory")
    private String name;

    @NotBlank(message = "Email is mandatory")
    private String email;
}
```

### Controller에서의 검증 처리  

```java
@Controller
public class UserController {

    @GetMapping("/signup")
    public String showSignUpForm(@ModelAttribute("user") User user) {
        return "add-user";
    }   

    @PostMapping("/adduser")
    public String addUser(@Valid @ModelAttribute("user") User user, 
                          BindingResult result, Model model) {
        // 검증 에러가 존재하는 경우 다시 등록 폼(add-user.html)으로 이동
        if (result.hasErrors()) {
            return "add-user";
        }

        userRepository.save(user);
        model.addAttribute("users", userRepository.findAll());
        return "index";
    }
}
```

- `@Valid` 어노테이션을 통해 해당 객체에 대해 설정된 검증을 실행

- `@Valid`가 붙은 객체에 대해 검증한 후, 에러가 발생한다면 `BindingResult` 라는 객체에 순차적으로 저장됨
