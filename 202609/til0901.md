## 1. `Profile`

- 실행 환경에 따라 서로 다른 설정값 / 빈을 유연하게 전환, 관리하기 위해 사용  

### 프로파일 설정 및 활성화 방법  

1. 설정 파일 분리: 특정 profile 전용 설정 파일을 따로 생성  
    - `application-{profile}.properties` 형태로 생성  
    (`application-prod.properties`, `application-test.properties` 등)  

    이후 `application.properties` 파일에 다음과 같이 지정  

    ```properties
    spring.profiles.active=prod
    ```

2. `@Profile` 어노테이션 활용: 설정 클래스나 `component`에 `@Profile("프로파일명")`을 명시하면 해당 프로파일이 활성화되었을 때만 빈으로 등록  

```java
@Profile("prod")    // prod일 때 아래 빈 활성화
@Configuration
public class ProdConfig {
    @Bean
    public CustomVO customVO() {
        return CustomVO.builder().mode("운영환경").rate(0.8).build();
    }
}
```

## 2. `Log`

**퍼사드(facade)**: 디자인 패턴의 일종으로, 복잡한 하위 시스템들의 인터페이스를 하나로 묶어 단일화된 인터페이스를 제공하는 패턴  

**로깅 퍼사드**: 로깅 api를 추상화해 놓은 인터페이스의 모음

- 로깅 구현체에 의존하지 않고 추상화된 퍼사드 인터페이스에 의존함으로써 실제 로깅 구현체가 바뀌어도 기존 코드를 수정할 필요가 없음  

- 로깅 퍼사드 예시: `SLF4J`, `Commons Logging` ..
- 로거 구현체 예시: `Logback`, `Log4j2`, `JUL` ..

### 로그 레벨 5단계

| 레벨 | 설명 | 주요 용도 |
| :--- | :--- | :--- |
| **TRACE** | 가장 상세한 추적 정보 | 변수 상태, 메서드 진입/탈출 등 가장 상세한 디버깅 |
| **DEBUG** | 디버깅 목적의 상세 정보 | 개발 및 테스트 환경에서 시스템 상태 확인 |
| **INFO** | 정상 작동 알림 정보 | **운영 기본값**. 서버 시작/종료, 주요 API 요청 완료 |
| **WARN** | 잠재적 문제 알림 경고 | 당장 장애는 아니지만 시스템 영향 가능성이 있는 상황 |
| **ERROR** | 기능 처리 불가능한 에러 | 심각한 예외 발생, 즉시 조치가 필요한 장애 상황 |

> **동작 규칙**: 설정한 로그 레벨 **이상**의 심각도를 가진 로그만 출력   
> `TRACE` -> `DEBUG` -> `INFO` -> `WARN` -> `ERROR`

---

### application.properties 로그 설정 예시

```properties
# 1. 루트(전체) 로그 레벨 설정
logging.level.root=info

# 2. 특정 패키지별 로그 레벨 설정
logging.level.com.basic.boot=debug
logging.level.org.springframework.web=info
```

## 3. Spring Data JPA

- **ORM (Object-Relational Mapping)**: 객체(Java)와 릴레이션(RDB) 간의 개념적 불일치를 해결하는 프레임워크
- **JPA (Java Persistence API)**: ORM을 위한 Jakarta/Java 표준 스펙  
- **Hibernate**: JPA 표준 명세를 실제로 구현한 대표적인 ORM 구현체
- **Spring Data JPA**: JPA를 더 쉽게 사용할 수 있도록 `Repository` 인터페이스 형태로 추상화하여 제공하는 스프링 모듈

---

### JPA 주요 설정 (`application.properties`)

- **`spring.jpa.hibernate.ddl-auto`**: 엔티티 기반 DB 테이블 자동 생성 옵션
  - `create`: 기존 테이블 삭제 후 새로 생성
  - `create-drop`: 시작 시 생성, 애플리케이션 종료 시 테이블 삭제
  - `update`: 기존 테이블은 유지하고 변경된 스키마만 반영  
  - `validate`: 엔티티와 테이블이 정상 매핑되었는지만 검증

---

### Entity 작성 및 Primary Key 전략

- `@Entity`: 엔티티 클래스임을 지정하며 DB 테이블과 매핑하는 객체를 나타내는 어노테이션  
    - 엔티티(Entity): 데이터베이스에서 표현하려고 하는 유형, 무형의 객체로서 서로 구별되는 것  
        - 이 객체들은 DB 상에서는 보통 table로 표현됨
        
- `@Id` : 엔티티의 기본키를 나타내는 어노테이션  
- `@GeneratedValue` : 프라이머리 키의 값을 자동 생성하기 위해 사용되는 어노테이션  

### Primary Key 자동 생성 전략 4가지 (`@GeneratedValue`)

- **`AUTO`** (기본값)
  - 사용 중인 데이터베이스 벤더(MySQL, Oracle 등)에 맞춰 Persistence Provider가 가장 적절한 생성 전략을 자동으로 선택
- **`IDENTITY`**
  - DB의 `AUTO_INCREMENT` 기능을 활용하여 레코드가 `INSERT`될 때 DB가 자동으로 PK 값을 1씩 증가시켜 할당
- **`SEQUENCE`**
  - 데이터베이스의 Sequence 객체를 사용하여 기본 키를 생성하는 방식 (예: Oracle, PostgreSQL 등에서 활용)
- **`TABLE`**
  - 키 생성 전용 별도 테이블을 만들고 이름과 값을 관리하여 PK를 생성하는 방식


- Entity 클래스 작성 예시

```java
@Entity
@Getter @Setter
public class Customer {
    @Id     // 기본키
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id; 

    @Column(unique = true)
    private String customerId;

    @Column
    private String customerName;
}
```

### Repository 인터페이스 

- `JpaRepository`를 상속받는 인터페이스를 작성하면 별도의 구현체 클래스를 작성하지 않아도 Spring Data JPA가 실행 시점에 구현체를 자동으로 생성
- **Query Method**: 메서드 이름을 규칙에 맞게 작성하면 메서드명과 매개변수(인자)를 분석하여 알맞은 SQL 쿼리를 생성하고 DB 데이터와 객체를 자동으로 매핑합니다.

#### Query Method 주요 키워드 및 생성 쿼리 패턴

| 키워드 예시 | 예시 메서드명 | 생성되는 쿼리 의미 (`WHERE` 절 등) |
| :--- | :--- | :--- |
| **`findBy...` / `getBy...`** | `findByCustomerId(String id)` | `WHERE customer_id = ?` (데이터 조회) |
| **`And` / `Or`** | `findByNameAndAge(String name, int age)` | `WHERE name = ? AND age = ?` (다중 조건) |
| **`Between`** | `findByAgeBetween(int start, int end)` | `WHERE age BETWEEN ? AND ?` (범위 조건) |
| **`LessThan` / `GreaterThan`** | `findByAgeLessThan(int age)` | `WHERE age < ?` (비교 조건) |
| **`Like` / `Containing`** | `findByNameContaining(String name)` | `WHERE name LIKE %?%` (문자열 포함 검색) |
| **`StartingWith` / `EndingWith`** | `findByNameStartingWith(String prefix)` | `WHERE name LIKE ?%` (접두사/접미사 검색) |
| **`OrderBy...Asc/Desc`** | `findByNameOrderByIdDesc(String name)` | `WHERE name = ? ORDER BY id DESC` (정렬) |
| **`countBy...`** | `countByStatus(String status)` | `SELECT COUNT(*) WHERE status = ?` (개수) |
| **`existsBy...`** | `existsByCustomerId(String id)` | 데이터 존재 여부 확인 (`boolean` 반환) |
| **`deleteBy...` / `removeBy...`** | `deleteByCustomerId(String id)` | `DELETE FROM ... WHERE customer_id = ?` |

#### Repository 작성 예시

```java
public interface CustomerRepository extends JpaRepository<Customer, Long> {
    // customerId 매개변수를 인수로 받아 자동으로 조회 쿼리 실행
    // 정의만 해도 spring data jpa가 자동으로 구현  
    Customer findByCustomerId(String customerId);
}
```
